File: client/src/pages/auth/LoginPage.tsx

2. Authentication Flow

2.1 Client-Side Flow

  1. User enters email + password and optionally checks "Remember Me"
  2. On submit, authApi.login(email, password) fires a POST /api/auth/login request
  3. On success: JWT token + user object are returned
  4. Token is stored in localStorage under key access_token via the Zustand auth store
  5. User object is set in the Zustand store
  6. Navigation occurs based on role

2.2 Server-Side Flow

  1. Request hits Express at POST /api/auth/login
  2. Passes through CORS → Helmet → Global Rate Limiter (300/15min) → Auth Rate Limiter (20/15min)
  3. Body validated against Zod loginSchema via validate() middleware
  4. Supabase query: fetch id, email, password_hash, role from users table
  5. If user not found: generic "Invalid email or password" (401) — no user enumeration
  6. bcrypt.compare() validates password against stored hash
  7. If invalid: same generic error (401)
  8. last_login timestamp updated in database
  9. JWT signed with JWT_SECRET; expiry set by role:
    • Admin: 2h
    • Staff / Alumni: 7d
  10. Response: { user: { id, email, role }, token }

3. Security Measures

3.1 Password Security

MeasureDetailsSeverity
Password Hashing bcryptjs with 12 salt rounds CRITICAL
Constant-Time Comparison bcrypt.compare() is inherently timing-safe CRITICAL
Generic Error Messages Both "user not found" and "wrong password" return: "Invalid email or password" — prevents user enumeration HIGH
Password Length Constraints Client: min 6 chars. Server: min 1 / max 128 chars MEDIUM

3.2 JWT Token Security

MeasureDetailsSeverity
Secret Validation Server validates JWT_SECRET is ≥ 32 chars at startup; hard exits if missing CRITICAL
Role-Based Expiry Admin tokens: 2 hours. Staff/Alumni: 7 days HIGH
Admin Token Age Enforcement Middleware checks iat claim; admin tokens older than 2 hours are rejected even if not yet expired HIGH
Algorithm HMAC-SHA256 (HS256) via jsonwebtoken MEDIUM
Payload Contents { userId, email, role } — no sensitive data (no password hash, no PII beyond email) MEDIUM

LimiterWindowMax RequestsApplied To

PREVENTION Brute-force login attempts are throttled to 20 per 15 minutes per IP.

3.4 Input Validation

LayerLibraryEnforcement
Client-Side Zod (loginSchema) email: .email(), password: .min(6)
Server-Side Zod (loginSchema) + .strict() email: .email().max(255), password: .min(1).max(128)
Middleware validate() Returns 400 with field-level errors on validation failure. Replaces req.body with parsed (sanitized) data on success.

NOTE Server schemas use .strict() which rejects any unknown/extra fields in the request body.

Observation: The login page does not use Cloudflare Turnstile. While rate limiting (20 req/15min) mitigates brute-force, adding Turnstile on the login page would provide an additional layer of bot protection.

3.8 Cross-Tab Session Management

  • Auth store listens for StorageEvent and visibilitychange events
  • syncToken() detects when another browser tab logs in/out and syncs state
  • On logout, localStorage is cleared and Zustand store is reset
  • useAuth hook decodes JWT payload on page load (client-side only, no verification) to restore session

3.9 Server-Side Authentication Middleware

File: server/src/middleware/auth.ts

  • authenticate — extracts Bearer token from Authorization header, verifies with jwt.verify(), attaches decoded payload to req.user
  • authorize(...roles) — role-based access control; returns 403 if role not in allowed list
  • Admin tokens undergo an additional max-age check (2 hours) independent of the JWT exp claim

8. Security Observations & Recommendations

Current Strengths

  • STRONG bcrypt with 12 salt rounds for password hashing
  • STRONG Generic error messages prevent user enumeration
  • STRONG Dual-layer rate limiting (global + auth-specific)
  • STRONG Admin tokens limited to 2-hour lifetime with server-side enforcement
  • STRONG Zod strict mode on server rejects unknown fields
  • STRONG JWT_SECRET validated at server startup (≥ 32 chars)
  • STRONG Helmet security headers applied globally
  • STRONG CORS restricted to single origin
  • STRONG OTP codes are bcrypt-hashed before storage
  • STRONG OTP resend cooldown (30 seconds per email+purpose)

Areas for Improvement

  • RECOMMENDATION Add Cloudflare Turnstile to the login page — Currently only registration and forgot-password have bot protection. Login is the most targeted endpoint.
  • RECOMMENDATION Account lockout mechanism — After N consecutive failed login attempts, temporarily lock the account (not just IP-based rate limiting).
  • RECOMMENDATION Login attempt logging/audit trail — Record failed login attempts for security monitoring.
  • RECOMMENDATION Password complexity requirements — Current minimum is 6 characters; consider requiring uppercase, lowercase, number, and special character.
  • INFO The "Remember Me" checkbox always stores in localStorage regardless of the checkbox state. The persist parameter is accepted but not differentiated.
  • INFO The login email input uses type="text" instead of type="email", which means no built-in browser email validation.
